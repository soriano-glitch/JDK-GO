## Findings

None found in reviewed scope. Five-axis check:

- A Behavior: upload is pinned to a single authenticated connection, and chunks are acknowledged in order by the size negotiated by the Host (at most 64 KiB); the commit path and length are validated, failure sends no question, and mutations aren't replayed automatically. Upload returns the workspace path and doesn't fake an attachment receipt; when a text model rejects an image, the same prompt ID is reused and switched to uploading the file path.
- B Contract: uses only the live `workspace.upload.v1`; the Harness endpoint allowlist isn't relaxed. Local/SSH keep the original attachment upload; the Chinese and English inputs and the guide were generated and synced.
- C Security: validates the basename, acknowledgement offset and `./name` return path, and doesn't log upload data; a failure does a best-effort abort. Whether it is writable, publication of same-named files and path/version limits are still decided by the Host.
- D Process: the modification scope was limited, and the branch and internal PR were submitted as the maintainer asked; no merge, publish or install, and in the end the dependency lock and generated configuration have no diff.
- E Scope: reuses the existing network details, with icon and host switching kept separate; no polling or new network measurement chain is introduced. The extra 20 MiB limit that the user asked to remove, and its dedicated UI validation, were removed.

## Coverage and residual risk

- Upstream basis: the [ds-harness-remote 0.6.2 / 479b943 protocol](<https://github.com/liguobao/ds-harness-remote/blob/479b94341c0d0de63846f21d0fcca26997d158d1/docs/protocol.md#L1529-L1648>) and the [Host implementation](<https://github.com/liguobao/ds-harness-remote/blob/479b94341c0d0de63846f21d0fcca26997d158d1/packages/plugin/src/workspace-upload.ts>), MIT; the source has been added to the [third-party notices](<../../THIRD_PARTY_NOTICES.md#L120-L148>).
- The app keeps the ordinary attachment's single-file 200 MiB and per-message total budget; the remote transport layer keeps only the protocol's absolute cap of 1 GiB. Relay/TURN, unknown paths or old plugins are typically still limited by the Host to 20 MiB, which can't be bypassed by changing the app.
- Protocol regressions cover declarations larger than 20 MiB being able to enter the Host open, with no file data read before the Host rejects; the rejection keeps the original error code. They also cover malformed acknowledgements, dangerous filenames, same-name renames, timeouts, connection retirement, failure cleanup and the exact RPC parameters on a real Noise channel.
- The initial local stage didn't run native UI tests; afterwards [CI 41691203233](<https://github.com/ccch1mneyyy/dsh-Go/actions/runs/41691203233>) actually executed all Flutter shards. Other checks passed, and Flutter 1 had 6 failures: 3 new tests queried a Tooltip as a label, 1 old geometry test picked up the split-out icon instead of the host control group, and 2 network-details goldens. The assertions were fixed per Flutter 3.47's tooltip semantics and the control group boundary, keeping the original tap/size/spacing requirements, and no tests were deleted or skipped.
- A submit timeout may already have landed on disk; a successful abort doesn't mean the committed file was deleted. Resuming uploads across connections or isolating malicious local host processes is not claimed.
