# Contract for reusing attachment references when exporting child sessions (649)

This optimization only reuses, on the internal ZIP descendants read path, the validated SessionEvent returned by persistence handle.read, avoiding JSON.parse-ing each just-serialized line again. The public readSessionLogText, sessionLogZipEntries and streamSessionLogZip parameters and return types are unchanged; the rootContent string is still parsed via the old path, compatible with direct callers and exports without child sessions.

First serializeSessionLog succeeds, then the declared attachment carriers are extracted from the same batch of events; serialization errors still close in finally. This relies on the persistence contract's JSON SessionEvent: it is not a new promise of serialization equivalence for arbitrary objects with toJSON/getters/mutable external state. Only the selected attachment references are kept, not the whole events array; there's no cross-request cache. The original collectEventAttachmentRefs function and selection rules are reused as is; unknown events and unrelated fields are still not interpreted.

The root-to-child-session order is kept, as are last-reference-wins for duplicate image IDs and file ID+name deduplication with insertion order. Each live session is still flushed first and then open/read/close; any read/serialization failure still aborts the ZIP. ZIP paths, byte contents, compression level, queue backpressure, cancellation signals, attachment integrity verification and stream reads are unchanged. A partial response already sent can't be rolled back, and no success guarantee is added.

Verification is clearly separated: the public route/Response/fflate and its own service fixture are used for exact repeated-parse counts; there is also a real Cordis+Session+JSONL create/append/flush/reopen/read/close chain. The latter's descendants list is still provided by an explicit query fixture, and it isn't called a full Host/real session-query/HTTP authentication/Android measurement.
