# Android system font discovery (#202)

The runtime startup environment provides `XDG_DATA_DIRS=/usr/local/share:/usr/share:/system` for Linux font discovery. The original system directory order is kept; the current libreoffice-kit appends `/fonts` to each entry, so it can discover `/system/fonts`, which PRoot already binds. User font directories are still discovered by the converter via HOME/XDG_DATA_HOME.

The login shell profile fills in the same default only when the variable is unset; an explicit empty string or a custom list is left as is. The main engine doesn't depend on the login shell, so the default goes directly into the launch template; an explicit value from the app's later GUEST_ENV still overrides it. A user's explicit office `fontDirectories` configuration still takes priority; this change doesn't override it and doesn't change `XDG_DATA_HOME`, font substitution rules or resource limits.

Direct startup resolves the same guest environment, and the new `/system/fonts` uses Android's real path. The existing Direct problem that `/usr/local/share` and `/usr/share` aren't mapped to physical paths inside the rootfs is unchanged; this item doesn't promise that all font sources are equivalent between Direct and PRoot.

Host comparison of the current 0.1.5 WASM on the original DOCX from #202: by default only DejaVu is embedded and the Chinese on the first page is blank; after adding the font root containing the existing NotoSansCJK TTC, NotoSansCJK is embedded and the Chinese on the first page is visible. In both cases missingFonts includes Microsoft YaHei, and in both cases the Chinese text can be extracted. Neither the missing-font list, text extractability nor full-page pixel differences can independently prove rendering correctness. This is only limited evidence for the discovery mechanism and a sample page, not a phone reproduction, full Chinese compatibility or complete typesetting acceptance.

`runtime/tests/test_font_environment.py` calls the real rtbuild generator and checks the default, the later override and the profile unset/custom/empty behavior through real env/sh. Rebuilding the runtime changes runtimeVersion because rtbuild.py's inputs change; the version is produced by the existing build process. This item doesn't change pins or dependencies. Not compiled for Android; JVM, PRoot, ARM, on-device font reading and document preview were not run.
