# Array paths in native plugin formulas match the app

Refs W17-B (plugin protocol compatibility; no new public issue).

`sdk/plugin-kit/lib/formula.js` is the counterpart of the app's bounded formula evaluator. Formula data comes from JSON; arrays can be read by non-negative numeric index, and the `length` property of the JavaScript array object itself must not be treated as a JSON data field. A field named `length` in a real object can still be read, and numeric string keys of objects keep their existing behavior.

The original SDK read arrays and objects with a uniform `hasOwnProperty`, so `data.rows.length` on an ordinary `{ rows: [2, 3] }` gave 2, and the public `checkView` didn't report the formula as missing. The app's `evaluateDshUiFormula` only accepts numeric indexes when reading a List via `dshUiLookup`, so the same formula's result is missing and leaves a diagnostic in `view.value`. Plugin authors therefore got local validation results that couldn't be reproduced in the app.

The fix only excludes dot fields when the SDK formula read path encounters an array, returning missing through the original failure exit. Formula syntax, operations, resource limits, JSON object fields, numeric indexes and `$` binding semantics are unchanged. No `length` operation is added, and the app's production source, layout, assets and protocol format are not modified.

## Golden and reproduction

`sdk/plugin-kit/test/formula-array-paths.test.js` checks ten cases through the actual `evaluateFormula` and `checkView`: `length` on non-empty, empty, nested and root arrays is missing with a `view.value` diagnostic; numeric indexes on arrays, nested arrays and root arrays are valid; object `length` as a number and as a decimal string are valid; object numeric keys are valid. On the original source, the first four cases fail and the last six already passed. The comparison uses no pseudo-arrays, custom properties or host objects.

Run from the repository root:

```sh
node --test sdk/plugin-kit/test/formula-array-paths.test.js
node --test sdk/plugin-kit/test/*.test.js
```

`app/test/plugins/view/plugin_formula_array_consumer_test.dart` additionally verifies, through the real `parsePluginView` and its formula evaluation entry, that array length is missing, legal indexes work and object length is 2. These three cases already passed on the app's unmodified source and serve as an independent compatibility reference; the expectation file generated by the SDK itself can't be treated as the sole evidence of consistency between both sides. The tests don't modify generated parity expectations, schemas, translations or assets.
