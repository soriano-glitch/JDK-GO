# HMR updates re-verify the install basis before actual removal

Refs W17-B. Base 63e255fab5cb9d817af30b631c3643ccce8e9231, with the runtime prerequisite being the 662 patch 06faae809abd12f31a4f55bc8c7fa6ca02572c5d296e5558e75320b4cbc9bc5f. The outer layer only adds this patch file and can be applied to a clean base; building the runtime requires 662 first, and this inner patch is not declared runnable without 662.

The ordinary public updateBundle first reads from, then asynchronously checks the registry. The HMR branch then removes the actual dependency and installs the target; if during the check another public update has successfully installed a newer version, the old check must not silently remove the newer version and then install an outdated target. If it has been successfully uninstalled, the old check's target must not be reinstalled either.

Pre-implementation agreement: reuse 662's internal per-update selection holder to pass expectedFrom, and inside removeBundle's original change file lock and the configure/HMR lock, before any deselect, reload or pnpm write, re-read the installed manifest version following the existing bundle resolution rules. The original not-removable check is still kept first: the already-uninstalled scenario is rejected by the original too, and it isn't reported here as a new defect or given a changed error code. If, after passing the removability check, the basis has changed, an ordinary Error is thrown, which the original change turns into the existing failed/operation-error, and update returns early along the original step=remove. No new RPC parameters, return fields, user configuration, caches or whole-update transactions.

An ordinary remove has no holder, so this restriction isn't added. After a target failure, the original recovery cleanup remove doesn't pass the holder, keeping the selection captured by 662 and the original recovery contract. The original platform, compatibility, removability, management-required, bundle-in-use and cancellation checks are not removed. Normal HMR updates and explicit ordinary install/remove behavior are unchanged.

The only new guarantee is that an installed version change is detected before this removal; a normal prior uninstall was already rejected by not-removable, and no new comprehensive existence protection is claimed. Same version with different content/source, ABA version changes, concurrency between stages after removal, external processes not respecting file locks, full update atomicity and guaranteed recovery success are not guaranteed. It isn't required to undo a second update that has already completed successfully.

Changes runtimeVersion; pins are not recorded. Not compiled for Android; PRoot/ARM not run. Verification used only its own local registry, the real CLI/HMR/PluginManager/pnpm and a temporary profile, without real accounts or device business plugins.
