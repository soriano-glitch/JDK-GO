# Error ownership for writing media private downloads to disk

Pre-implementation agreement: keep using the existing MediaError.storage, without adding protocol fields or error codes. The ordinary call path is media-engine's video task succeeded → createStreamStager → writeStagedChunk; when HTTP has returned normally, a local write failure should not report network (unable to connect to the generation service).

This patch converts native failures to storage only at the explicit call boundaries of local file write, sync and normal close. Failures of network requests and response reads are still network; existing MediaErrors are kept as is. Timeouts/active cancellation are handled first by the existing control.signal; when safe cleanup can't be confirmed, cleanup_failed still takes priority. Partially written files are still cleaned up after verifying the original inode/directory identity; the contract for committing or deleting artifacts is unchanged.

A real Linux own process with RLIMIT_FSIZE=1024, ignoring SIGXFSZ for that test process, uses 8192 bytes of local HTTP to trigger a real short write followed by EFBIG. The original correctly rejected and cleaned up, but misreported network. 512 bytes under the same limit succeeds, and 8192 bytes without the limit succeeds, both preserving the original bytes/hash; on failure the existing non-temporary file is kept. This limit applies only to the test subprocess; it doesn't simulate write returns and doesn't change the machine's global quota. sync/close platform faults that can't be verified here are only described by the source error boundaries, with no false claim of covering real faults.

The standalone media npm bundle is not in the patches/bridge/boot/direct set of the current runtime/build-runtime.sh inputs_sha, so it doesn't change the current runtimeVersion. After applying the source, the media plugin must be repackaged and installed; this patch doesn't specify/publish a new version and doesn't modify build configuration or pins. Not compiled for Android; PRoot/ARM not run.
