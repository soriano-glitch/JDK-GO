# Session enumeration and the runtime control namespace

The exact sessions-root `.dsh-go-lifecycle` is the lease and tombstone control directory owned by this runtime's deletion seam, not a JSONL project directory. `listProjectDirs` excludes only this reserved name; it doesn't exclude other directories by dot prefix, and doesn't change legal dot-leading SessionIds. Currently upstream encodes projects with a cwd as `--...--` and without a cwd as `_no-cwd`, neither of which can produce this reserved name.

This enumeration is shared by the public list, findLog, the historical corpus fingerprint and strict root encoding, so the exclusion applies to these entry points; the mixed compression, legacy flat, root directory errors, cancellation and 676's per-item isolation rules for other real projects are unchanged. The direct stat of deletion markers, the writer's identity/artifact dual leases and mutation's direct lease entry points are fully kept, and don't rely on scanning the control directory as a project.

In a limited real observation with 12 sessions, the original additionally read the control directory plus 12 ID slots and _mutations, 14 reads; after the fix these 14 are 0, and the list still returns the 12 correct IDs. Data of the same shape with 48 sessions saves 50 control-tree directory reads. This only proves redundant I/O is eliminated, not that phone startup latency improves, and it isn't treated as the root cause of the slow devices in #38/#57; the old permission fault in #527 has been handled by other work and is not delivered again. PRoot/Android not tested, not compiled for Android; the vendor patch and pins change the runtimeVersion computed by the build.
