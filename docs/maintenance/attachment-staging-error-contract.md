# Error ownership when preparing the attachment staging directory

Base 63e255fab5cb9d817af30b631c3643ccce8e9231, DSH 0.2.2-rc.1. The public admitEncodedFile declares that storage failures throw AttachmentError, and delegates to the real AttachmentStore.saveFile. LocalAttachmentStore's original stageImmutableObject placed directory preparation before the existing try/catch, so when an ordinary directory location was occupied by an existing file, mounting still succeeded but later saves leaked native EEXIST/ENOTDIR, while later open/write failures already had the ATTACHMENT_WRITE_FAILED classification.

This change only brings ensureDurableHome, ensureDurableDirectory and random temporary path generation into the same existing catch. When the temporary path hasn't been generated yet, removeTemporary is not executed, so cleaning up an uncreated path doesn't mask the original directory failure. The existing priority of handle closing, temporary cleanup, preserving AttachmentError as is, and preserving cancelled-signal errors is unchanged. cause keeps the real filesystem error; no error codes or RPC fields are added, and path permission policy/publication timing/file contents are unchanged.

The real public test, before the service is mounted, creates ordinary conflicting files in its own home at the attachments, attachments/v1 and attachments/v1/tmp locations respectively; only after mounting succeeds does it call saveFile/admitEncodedFile. A failure must not delete or rewrite the conflicting file; after it is moved away normally, the same instance can recover storage and read back exactly. It also checks normal binary/stream, the identity of a pre-cancelled reason, and tmp cleanup. This test doesn't simulate IO, change permissions or use real user data; there is no HTTP/full Agent/UI/device acceptance.

654 only changes the write/sync/close classification of the own media video stream-staging, and 679 only changes this official module's image displayName; this package alone doesn't include them. Changes runtimeVersion; not compiled for Android; Refs W17-B, no corresponding public issue number. Pins are not changed; the version is produced by the existing local build process.
