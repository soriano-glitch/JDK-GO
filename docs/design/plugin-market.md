## 3. Data: two files

Both are generated by the market repository's CI and published to GitHub Pages (`MARKET_SOURCE_URL`, default `https://ccch1mneyyy.github.io/dsh-go-market/`). The app doesn't read from there directly:

```
GitHub Pages
  → Worker Cron (every 10 minutes, src/market.ts publishMarket): fetch the two files and validate them together (validateCatalog)
      pass → write to the public bucket dshgo-dl at market/index.json, market/dsh-go.json
             (application/json; charset=utf-8, Cache-Control: public, max-age=300),
             and store the same snapshot in the Worker's own cache (KV)
      fail → write nothing; the bucket and cache still hold the previous copy
  → https://dl.dshtui.com/market/…   From app 1.0.9 on it reads here first (the CDN caches by max-age, not going through the Worker)
  → https://go.dshtui.com/market/…   The Worker serves the same snapshot as usual, as a fallback;
                                      old app versions coming here are 302'd to dl by the zone's Redirect Rule (web requests carrying an Origin header aren't redirected,
                                      and still get the Worker's CORS headers)
```

- `https://go.dshtui.com/market/index.json` (= `https://dl.dshtui.com/market/index.json`): **format 1**, which must pass the official DSH 0.2.1 validator (`dsh-plugin-market-index`). DSH Web and dsh-TUI can also add this address directly. Each plugin **lists only its one pinned version**.
- `https://go.dshtui.com/market/dsh-go.json` (= `https://dl.dshtui.com/market/dsh-go.json`): things format 1 can't hold, used by the app.
- The two files are cached separately on the CDN, so within 5 minutes after the catalog changes you may get a mismatched old/new pair: the app displays as usual (sidecar entries whose version doesn't match are not used), but doesn't store it, and fetches again next time (§6).

```jsonc
// dsh-go.json
{
  "schema": 1,
  "generatedAt": "2026-10-30T12:00:00Z",
  "plugins": {
    "@ccch1mneyyy/dsh-media": {
      "version": "0.2.0",              // matches the pinned version in index.json
      "tier": "official",              // official | community
      "title": { "zh": "生图生视频", "en": "Images & video" },
      "summary": { "zh": "…", "en": "…" },
      "screenshots": ["https://…"],     // https, at most 4
      "dshGo": {
        "adapted": true,               // uses the JDK-Go native protocol (cards, forms, settings page)
        "minApp": "1.0.3",             // apps older than this version only display it and don't allow installing
        "features": ["native-cards", "settings-page", "media"]
      },
      "risk": {
        "level": "low",                // low | medium | high, computed by CI per the rules below
        "flags": ["network"]           // see §5
      },
      "integrity": "sha512-…",         // npm dist.integrity, verified before installing
      "checkedAt": "2026-10-30T11:58:00Z",
      "blockedVersions": []            // versions taken down: users who already installed them see a warning
    }
  }
}
```

## 4. Market repository and submission flow (GitHub, automatic listing)

Public repository `ccch1mneyyy/dsh-go-market`:

```
plugins/<package name, in @scope__name form>.json   One file per plugin (submitted by the author)
schema/plugin.schema.json
scripts/check.mjs                         Automated checks
scripts/build.mjs                         Generates index.json + dsh-go.json
.github/workflows/check.yml               Runs the checks on PRs, and auto-merges if all pass
.github/workflows/publish.yml             Generates and publishes after merging
.github/workflows/watch.yml               Once a day checks for new versions of listed packages and opens PRs automatically
```

The entry the author submits:

```jsonc
{
  "name": "@someone/dsh-weather",
  "version": "1.2.0",
  "title": { "zh": "天气", "en": "Weather" },
  "summary": { "zh": "…", "en": "…" },
  "category": "tools",
  "screenshots": [],
  "homepage": "https://github.com/…"
}
```

Flow: the author opens a PR → `check.yml` runs the checks → if all pass and only one `plugins/*.json` was changed → auto-merge → `publish.yml` generates the two files → a few minutes later it can be seen in the app. `tier: official` can be set only by the repository maintainers, and a community PR carrying this field fails outright. An author upgrades by changing the version number and opening a PR again, equally automatic.

## 5. Automated checks and risk flags

**Blocked (not merged)**: this exact version doesn't exist on npm; no license or not an OSI license; format 1 validation fails; package over 50 MB; high-severity in npm security advisories; the author falsely claims `tier: official`.

**Allowed but flagged with risk** (`risk.flags`, shown to users in the app):

| flag | How it is judged | Level |
|---|---|---|
| `install-scripts` | `package.json` has preinstall / install / postinstall | high |
| `native-code` | The package contains `.node`, `binding.gyp` or prebuilt binaries | high |
| `shell` | The source calls child_process / executes commands | medium |
| `network` | The source has network requests (fetch, http, ws) | low |
| `filesystem` | Writes to paths outside the workspace | medium |
| `obfuscated` | Large minified or obfuscated files that are hard to review | medium |
| `not-adapted` | No JDK-Go native protocol declaration | low (goes to the "All" logic, not the "Adapted" section) |

`risk.level` takes the highest among all flags. The judgment is heuristic, and both the docs and the app say so: "Features found by automated checks don't mean the plugin is malicious."

## 6. App side

- The market page has three sections: Official / Adapted for JDK-Go / All. The first two come from the official index, and the third is dshfind.
- Reading the official index (from 1.0.9, `app/lib/state/plugins_state.dart` `fetchOfficialMarket`): first `https://dl.dshtui.com/market/`, and if that fails `https://go.dshtui.com/market/`. The most recent catalog that was readable and whose listing has a pinned version for every plugin is stored on the phone along with the ETags of the two files (SharedPreferences `market.official`): within 6 hours it is used directly with no request; after 6 hours it is re-validated with `If-None-Match` (a 304 extends it); pull-to-refresh and "Retry" always re-validate; when both addresses can't be reached the copy on the phone is used (however old). When the phone has none, as before: nothing published anywhere (404) is an empty market, and anything else is an error.
- Card: section badge + risk label (low isn't shown, medium is yellow, high is red).
- Detail page: screenshots, Chinese description, an item-by-item explanation of risks, version, source link.
- Install: install to the current host, using the version pinned by the index (`name@version`), verifying integrity before installing. medium / high first show a confirmation listing the risks.
- Update: for an installed official-index plugin, "Update available" shows when the index has a newer version. When the installed version is in `blockedVersions`, a warning and an uninstall entry are shown.
- Submission: at the bottom of the market page, "Submit a plugin" opens the market repository's submission instructions.
- Sharing: a plugin's details can share the link `https://go.dshtui.com/p/<package name>`; the web page shows the card, and tapping it wakes the app into the details.
- Image/video generation: when the current host doesn't have the media plugin installed but the official index has it, the "Generate" entry still shows, and tapping opens "Install on this host" (`MediaPluginState.installable`), rather than being hidden entirely.

### Install validation boundary (app implementation)

Before deleting the old version or starting installation, the app reads the exact version's `dist.integrity` through the existing `ShareNet.npmFacts` (official npm registry first, npmmirror as backup) and compares it with the sidecar. For entries that provide integrity, a mismatch or a temporary inability to look it up stops the install; cancelling or switching host also doesn't continue to start the install.

This can only check the **registry's version metadata**. The existing `pluginManager/inspect` and the parameters and return values of `installBundle` support neither passing an expected integrity nor reporting the digest of the package actually downloaded; the host-side pnpm verifies the tarball according to the registry it uses, and the app cannot prove that tarball matches the package the market checked. Closing end-to-end validation requires the host install API to accept and enforce an expected integrity. When the sidecar is missing, corrupt or version-mismatched, its check badges aren't shown; these entries use the original install path and don't claim to have completed market validation.

Plugin sharing reuses the existing `dshgo://` scheme: the web page hands `https://go.dshtui.com/p/<encoded package name>` over as `dshgo://go.dshtui.com/p/<encoded package name>`, and the app opens the details. Opening the same-path HTTPS link inside the app can also be parsed; whether Android directly takes over HTTPS still depends on the backend's App Links verification configuration.
